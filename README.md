# MyAI 私人 AI 聊天助手

一个可部署到 HTTPS 静态网站、并添加到 iPhone 主屏幕的 PWA。支持：
- OpenAI 兼容 Chat Completions 接口
- Anthropic Messages 接口
- 手动配置多个模型并切换
- 本地保存聊天记录
- 流式回复和停止生成（保留已收到的部分）
- 按标题、消息、文档文字搜索历史对话
- 删除单个对话，或清空全部对话并保留连接设置
- 提取 PDF、Word .docx 文字并随消息交给模型
- 提取 Excel .xlsx / .xls、CSV 的多个工作表和单元格，保留行号和列字母
- 可选联网搜索新闻和知识，展示接口实际返回的来源链接
- 默认详细回答，可切换简洁 / 标准 / 详细，并保留自定义提示词
- Markdown 渲染
- 上传最多 4 张图片进行视觉问答（取决于模型和中转站能力）

## 重要说明
1. 本项目是个人自用的前端原型。API Key 存在当前浏览器 localStorage 中，不适合公开给多人使用。
2. 浏览器直接请求中转站，需要中转站允许网页来源的 CORS 请求。
3. OpenAI 协议图片格式使用 `image_url`；Anthropic 使用 `image` + base64。中转站需完整支持对应格式。
4. Anthropic 请求使用 `x-api-key`、`anthropic-version` 和 `anthropic-dangerous-direct-browser-access` 请求头。部分中转站可能只接受 Bearer Token 或不允许浏览器直连；如遇此情况需按服务商文档调整或增加后端代理。
   QOPS（`api.gateway.qops.build`）使用 Bearer 认证，并由网关提供 API 版本；网页会为该域名省略其 CORS 策略不允许的 Anthropic 请求头。
5. 目前不包含语音、OCR、后端代理和跨设备同步。
6. 聊天记录及图片保存在浏览器本机，清理 Safari 网站数据可能导致记录丢失。图片会压缩后保存，但大量图片仍可能占用本机存储。

## 本地预览
PWA / Service Worker 需要 HTTPS 或 localhost。不要直接用 `file://` 打开。
在电脑安装 Python 后，在项目目录运行：
```bash
python -m http.server 8000
```
浏览器打开 `http://localhost:8000`。

## 部署到 GitHub Pages（免费静态托管）
1. 注册或登录 GitHub，创建一个 Public 仓库，例如 `myai-chat`。
2. 将本项目所有文件上传到仓库根目录。
3. 打开仓库 Settings -> Pages。
4. 在 Build and deployment 中选择 Deploy from a branch。
5. Branch 选择 `main`，目录选择 `/ (root)`，保存。
6. 等待 GitHub Pages 发布，打开页面提供的 HTTPS 地址。

如果使用 GitHub Pages，仓库内容是公开的；本项目没有把 API Key 写进代码或仓库，填写的 Key 只保存在你自己的浏览器里。不要把真实 Key 写入任何项目文件。

## iPhone 添加到主屏幕
1. 用 iPhone Safari 打开部署后的 HTTPS 地址。
2. 点击底部分享按钮。
3. 选择“添加到主屏幕”。
4. 确认名称为 MyAI，点击添加。
5. 从主屏幕图标打开。

## 填写接口
打开右上角设置：
- 接口协议：按中转站支持情况选择 OpenAI 或 Anthropic。
- Base URL：通常填 `https://域名/v1`。不要填 Key。
- API Key：粘贴你自己的 Key。
- 模型列表：每行填写一个模型 ID。
- 默认模型：填写其中一个模型 ID。
- 保存设置，然后点击“测试连接”。

### 导入加密连接配置
支持扫描配置二维码，或在设置中点击“导入加密连接配置”选择 `.myai` 文件，输入独立提供的 12 位配置码。连接设置通过 PBKDF2-SHA256（200,000 次）和 AES-256-GCM 加密，配置码不会放在链接或文件内。二维码使用 URL 片段传递密文，片段不会发送给网站服务器，导入时会从地址栏移除。配置仅保存在当前浏览器，不会同步到其他设备或浏览器环境。请妥善保管配置文件与配置码。

### iPhone 桌面版没有 Safari 的设置
Safari 和添加到主屏幕的网页可能使用独立存储。请从**桌面 MyAI 图标**打开设置，选择“扫描配置二维码（拍照 / 相册）”，拍摄电脑显示的配置二维码，或选择已保存的二维码原图，然后输入配置码。也可以导入 `.myai` 文件或粘贴完整的加密配置链接。必须在桌面版内完成一次导入，之后关闭重开会从桌面版本机存储恢复，不需要重复填写 URL / Key。网页不会从 Safari 读取其他容器中的密钥。

### 个人免配置入口
支持专属的 v2 配置二维码 / 链接 / `.myai` 文件。扫描后自动导入 URL、Key、协议和模型，直接返回聊天页，无需登录、填写接口或输入配置码；普通 v1 加密配置仍需原配置码。v2 使用随机 AES-256-GCM 密钥，并将解密材料一同放在私有链接片段里，因此**持有该二维码或链接的人就能获取接口凭证**；它是个人访问凭证，不能公开、转发或上传 GitHub。链接片段会保留在地址栏，便于收藏书签或“添加到主屏幕”后打开即用（片段不会发送到服务器）；同一链接再次打开时若连接未变则不覆盖本机设置。导入后会自动从 `/v1/models` 拉取当前协议可用的模型。个人二维码及文件只在部署目录外的本地忽略目录生成，公共网页和仓库不包含任何专属配置。首次使用桌面版时，仍须在桌面版内扫码一次，其后从桌面图标直接使用。

## 新功能使用
- **流式输出**：发送后随接口返回逐步显示，点击“停止”取消请求，保留已收到的文字。OpenAI Chat Completions 与 Anthropic Messages 的 SSE 均支持；接口若返回普通 JSON，则一次显示完整回复。接口断流会提示，部分回复会保留。
- **搜索与删除**：点击左上角会话菜单，在搜索框输入标题或消息关键词，也会检索附件提取文字。每个对话右侧“×”可删除，底部可清空全部对话；均需确认。清空对话保留 URL、Key 和模型设置。
- **文档**：点击输入框上方“文档”，选择 `.pdf` 或 `.docx`，提取完成后输入问题并发送。支持每次最多 3 个、每个 10MB、PDF 最多 120 页、每份 6 万字符、合计 12 万字符；超过限制明确报错，不会静默截断。扫描 PDF 需要先 OCR，旧版 `.doc` 需另存为 `.docx`。仅提取文字，不分析文档内的图片或保留版式。完整历史中的附件文字会随后续消息继续发送，受模型上下文和接口额度限制。
- **Excel / CSV**：点击“文档 / 表格”，选择 `.xlsx`、`.xls` 或 `.csv`。按工作表名称、原始行号、列字母提取单元格显示文字，保留多个工作表，包括明确标注的隐藏工作表。支持 UTF-8 和 GB18030 / GBK 中文 CSV。公式使用文件内的保存结果，不重新计算；没有保存结果则标明公式。空单元格省略、合并区域只保留左上角值，图表、图片和宏不提取也不执行。最多 30 个工作表、15000 个非空单元格，并遵守上述文件和文字总量限制；过大时明确报错，请拆分。文档文字进入历史消息后可参与对话搜索。
- **联网**：点击“联网”开启，再提问新闻、实时信息或知识问题。当前 QOPS Claude 配置已实测支持 Anthropic 服务端 `web_search_20250305`；工具调用通过原有接口认证，最多 3 次搜索，不需要额外搜索 Key。OpenAI 兼容接口使用 `web_search_options`，须由服务商和所选模型支持。接口不支持时会提示错误，可关闭联网后继续聊天；不会静默冒充已搜索。联网来源列出接口实际返回的 URL，并在新页面打开。搜索费用按服务商规则计算，来源真实性和新闻日期仍需核实。

解析组件以固定版本随项目托管：PDF.js 4.10.38、Mammoth 1.11.0、jsQR 1.4.0、SheetJS 0.20.3（npm 镜像 `@e965/xlsx`，下载时核对包 SHA-512），许可证在 `vendor/`。PDF 的可选 CMap / 标准字体从固定版本 jsDelivr 加载（首次解析某些中文 PDF 时需联网）。文档在当前设备解析，发送前不会传给模型；发送后提取文字将发送到配置的模型接口。聊天和文档文字仍使用浏览器 localStorage，大量记录需及时清理。

### URL 拼接规则
OpenAI：
- Base URL `https://host/v1` -> 请求 `https://host/v1/chat/completions`
- 如果 Base URL 已经以 `/chat/completions` 结尾，则直接使用。

Anthropic：
- Base URL `https://host/v1` -> 请求 `https://host/v1/messages`
- 如果 Base URL 已经以 `/messages` 结尾，则直接使用。

如果你的中转站要求不同路径、不同认证头或自定义请求体，需要根据中转站文档修改 `app.js` 中的 `endpoint()` 和 `callAI()`。

## 常见问题
- **Failed to fetch / CORS**：中转站未开放浏览器跨域，或 HTTPS 页面请求了 HTTP 地址。需要中转站开启 CORS，或部署一个后端代理。
- **401 / 403**：检查 Key、权限和认证头格式。
- **404**：检查 Base URL 与接口路径拼接。
- **模型不存在**：检查模型 ID 是否是中转站实际支持的 ID。
- **图片报错**：确认所选模型有视觉能力，中转站允许图片输入，且协议格式兼容。
- **Anthropic 浏览器请求失败**：部分服务商不支持浏览器直连或不支持相关请求头，需要使用服务商指定的兼容方式或后端代理。

## 安全建议
如果准备长期使用，建议改成“前端网页 + 自己的后端代理”结构，由后端保存 API Key，并限制访问来源、请求频率和额度。不要把 Key 硬编码进 HTML、JS、Git 仓库或公开链接。

## 回答质量与详略
默认加入中文回答、事实核对、附件引用和充分分析的指导；旧配置无需重新导入即采用“详细”。设置中的“回答详略”可选简洁、标准、详细，用户在问题中明确要求的语言和篇幅优先。自定义系统提示词继续保留并附加。Anthropic 单次输出上限提高到 8192 tokens，这是容量上限，不是强制输出长度；OpenAI 兼容协议沿用服务商默认输出上限。接口返回长度截断时会提示发送“继续”。更详细的回答可能增加时间和费用，提示词和容量调整不保证模型正确性，实际能力取决于所选模型和服务商。
